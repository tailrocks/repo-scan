# CI

## Generator ownership and pin

`.github/workflows/ci.yml`, `.github/actionlint.yaml`, and the marked shared
actions under `.github/actions/` are generated by `velnor-actions` from
[tailrocks/velnor-new](https://github.com/tailrocks/velnor-new). This checkout
uses the official Velnor Actions 0.1.4 release, from source commit
`d3590d321e51f7b99bfb0a92c11d3d6eb7af61cd`. Its release artifact URLs and
SHA-256 digests are recorded in `.velnor/release-manifest.json`; repository
settings are in `.velnor/config.toml`.

Velnor owns its declared generated paths, the complete
`.github/workflows/` namespace, and marked shared actions. Generation replaces
emitted managed files and retires managed files that are no longer emitted.
Other files under `.github/` are repository-owned and preserved. Change the
inputs and run `velnor-actions generate`; do not hand-edit generated files.
Keep custom workflows outside `.github/workflows/`. Exact action and tool
versions are pinned in generated output; consult it for current values rather
than maintaining a second pin list here.

## Current workflow

`ci.yml` runs for pull requests, pushes to `main`, and merge groups. All jobs
run on `ubuntu-24.04`:

| Job | Timeout | Purpose |
| --- | ---: | --- |
| `actionlint` | 10 min | Lint GitHub Actions workflows. |
| `plan` | 20 min | Check generated-file consistency and create the Velnor task plan. |
| `rust-repo-scan` | 30 min | Run formatting, Clippy, unit and integration tests, doctests, and documentation checks; upload the Velnor crate report. |
| `required` | 10 min | Aggregate the plan, Rust, and actionlint job results. |
| `publish-baseline` | 10 min | On pushes to `main` after `required`, upload a Velnor baseline JSON artifact. |

`publish-baseline` publishes CI baseline data, not a `repo-scan` executable.
The Rust job has no binary packaging or release step.

## Binary release state

The published Velnor Actions 0.1.4 release does not emit a consumer-selectable
binary-release workflow for repo-scan. There is no repo-scan binary-release
workflow in `.github/workflows/`: the only workflow there is `ci.yml`, which
has no tag trigger. This repository therefore does not currently build or
publish downloadable repo-scan binaries through GitHub Actions. Revisit this
section when a verified Velnor release can generate the repo-scan binary
publisher and the generated workflow is enabled here.

## Other checks

`docs/workflows/audit.yml` is an audit workflow specification, not an active
GitHub Actions workflow: it is outside `.github/workflows/`. The repository
has no active `audit` status check; see [AUDIT_GATE.md](AUDIT_GATE.md). The
`Required` job is the generated CI aggregate. Branch-protection settings are
managed outside this repository.
